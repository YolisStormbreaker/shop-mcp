# shop-mcp

MCP-сервер для поиска на Авито, Ozon, AliExpress, Wildberries, Яндекс Маркете, Lamoda и в Золотом яблоке под своим аккаунтом. Он управляет обычным Chrome, в котором вы уже вошли на эти сайты, и отдаёт результаты компактным TSV, а не снимками страниц. Так поиск стоит сотни токенов, а не десятки тысяч.

Что умеет:

- Авито: поиск с ценой доставки в ваш город и итоговой суммой, карточка объявления с адресом.
- Ozon: поиск, карточка товара (характеристики, дата доставки, продавец и его юрлицо: видно, из-за рубежа ли товар), корзина (положить, посмотреть, убрать), история заказов с поиском по названию товара.
- AliExpress: поиск, карточка с датами доставки и всеми вариантами (sku, цена, остаток), корзина, история заказов с поиском по названию товара.
- Wildberries: поиск (страницы по 100, сортировки, цена), карточка (продавец, наличие, оценка срока доставки, характеристики), корзина (посмотреть, положить, убрать).
- Яндекс Маркет: поиск (страницы, сортировки, цена) с ценой с картой Я Банка и без, пометками продвижения и «из-за рубежа»; карточка с магазином и доставкой; корзина (посмотреть; положить и убрать — только в видимой вкладке).
- Lamoda: поиск с итоговой ценой со всеми скидками и размерами в наличии; карточка с остатками по размерам и возвратом; корзина (посмотреть, положить, убрать).
- Золотое яблоко: поиск (страницы по 24, сортировки, цена), карточка с ценой и наличием каждого объёма, составом и применением, корзина (посмотреть, положить, убрать).

Заказы сервер не оформляет и ничего не оплачивает: всё заканчивается на корзине.

## как устроено

Chrome запущен с отдельным профилем и `--remote-debugging-port=9222` на 127.0.0.1. Сервер подключается к нему по DevTools Protocol, держит по одной вкладке на сайт и вызывает собственное API сайта через `fetch()` изнутри вкладки. Cookies и авторизация остаются в профиле Chrome, в коде их нет.

У меня Chrome и сервер живут на отдельном Mac mini, а Claude Code ходит к нему по ssh. Запускать можно и на той же машине.

## установка

1. Положить репозиторий в `~/shop-mcp` и поставить [uv](https://docs.astral.sh/uv/) (зависимости описаны в заголовке `server.py`):

   ```sh
   git clone https://github.com/YolisStormbreaker/shop-mcp.git ~/shop-mcp
   brew install uv
   ```

2. Запустить Chrome с отдельным профилем и отладочным портом. LaunchAgent `launchd/local.shop-chrome.plist` запускает его при входе в систему, прячет окно, чтобы он не мешал на рабочем Mac, и даёт ему свою иконку в Dock:

   ```sh
   sed "s/YOU/$USER/" ~/shop-mcp/launchd/local.shop-chrome.plist > ~/Library/LaunchAgents/local.shop-chrome.plist
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.shop-chrome.plist
   mkdir -p ~/.local/bin && ln -s ~/shop-mcp/shop-chrome ~/.local/bin/shop-chrome   # show | hide | restart | icon
   curl -s http://127.0.0.1:9222/json/version   # ответ JSON — Chrome на месте
   ```

3. `shop-chrome show`, войти в этом Chrome на все сайты и указать адрес доставки, `shop-chrome hide`. Вкладки сайтов не закрывать.
4. Подключить MCP-клиент на этом же Mac:
   - Claude Code: `claude mcp add shop -s user -- ~/shop-mcp/run.sh`
   - Claude Desktop: в `~/Library/Application Support/Claude/claude_desktop_config.json`, раздел `mcpServers`, добавить `"shop": {"command": "/Users/YOU/shop-mcp/run.sh"}` и перезапустить приложение (⌘Q).
   - Другой компьютер — см. следующий раздел.

Лог вызовов пишется в `logs/shop.log`, тела неудачных ответов — в `logs/bodies/`. В них бывают ваши данные со страниц сайтов, поэтому `logs/` в `.gitignore`.

## подключение с другого компьютера

Chrome со входами и сервер остаются на Mac, где всё установлено (дальше — хост). Агент на другом компьютере запускает сервер по SSH: MCP идёт через stdin/stdout этого соединения, наружу не открывается ни один порт. Всё выполняется под аккаунтами владельца хоста: его адрес доставки, его корзины.

**На хосте, один раз (делает владелец):**

1. Включить вход по SSH: Системные настройки → Основные → Общий доступ → Удалённый вход, доступ только своему пользователю.
2. Взять у агента публичный ключ и дописать его одной строкой в `~/.ssh/authorized_keys` с ограничением: этот ключ сможет только запустить сервер, без шелла и проброса портов.

   ```
   command="/Users/YOU/shop-mcp/run.sh",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty ssh-ed25519 AAAA… shop-mcp-agent
   ```

3. Хост должен быть доступен по сети: в одной локальной сети — по имени `ИМЯ.local` (Системные настройки → Основные → Общий доступ → Локальное имя хоста), из другой сети — через VPN вроде Tailscale. Порт 22 в интернет не пробрасывать.

**На компьютере агента:**

1. Создать ключ и отдать владельцу хоста публичную часть (`~/.ssh/shop_mcp.pub`):

   ```sh
   ssh-keygen -t ed25519 -f ~/.ssh/shop_mcp -N "" -C shop-mcp-agent
   ```

2. Один раз подключиться вручную, чтобы принять ключ хоста. Сервер запустится и будет ждать ввода — выйти через Ctrl-C:

   ```sh
   ssh -i ~/.ssh/shop_mcp YOU@HOST
   ```

3. Подключить MCP-клиент (команду на хосте задаёт ключ, указывать путь не нужно):
   - Claude Code:

     ```sh
     claude mcp add shop -s user -- ssh -i ~/.ssh/shop_mcp -o BatchMode=yes -o ServerAliveInterval=30 YOU@HOST
     claude mcp list   # shop … ✔ Connected
     ```

   - Claude Desktop — в `claude_desktop_config.json`, раздел `mcpServers`, затем перезапуск приложения:

     ```json
     "shop": {
       "command": "ssh",
       "args": ["-i", "/Users/АГЕНТ/.ssh/shop_mcp", "-o", "BatchMode=yes", "-o", "ServerAliveInterval=30", "YOU@HOST"]
     }
     ```

   - Cursor, VS Code, Codex и другие клиенты — та же команда `ssh` с теми же аргументами.

**Что нужно знать агенту:**

- Как пользоваться инструментами и что работает, а что нет, сервер сообщает сам: в инструкциях при подключении и в описаниях инструментов.
- Капчу и вход на сайт проходит только владелец на хосте (`shop-chrome show`, пройти, `shop-chrome hide`). Ответ с «⚠️ … shop-chrome show» — передать владельцу: с ограниченным ключом агент эту команду не выполнит.
- Клики — адрес в `avito_item`, добавление в корзину AliExpress, корзина Яндекс Маркета — работают, только когда на хосте окно Chrome показано и открыта вкладка этого сайта.
- `*_add_to_cart` и `*_remove_from_cart` меняют корзины владельца — только по его явной просьбе. Заказы сервер не оформляет.
- Браузер на хосте один на всех: не делать параллельных вызовов к одному сайту, и не одновременно с агентом на самом хосте — вкладка сайта общая.
- Есть и HTTP-режим (`server.py --http`, 127.0.0.1:8765, порт задан в коде), но без авторизации: только через SSH-туннель. SSH-вариант выше проще.

## мониторинг Авито в Telegram

`watch.py` ищет по всей России с Авито Доставкой новые Raspberry Pi 4/5 и Orange Pi 3/4/5/Zero 2W, у которых цена с доставкой не больше 6 000 ₽. Зарезервированные пропускает. Каждое объявление присылает один раз. Запросы и порог цены задаются в начале файла.

1. Создать бота у @BotFather и положить токен в `telegram.json`: `{"token": "..."}`.
2. Написать боту /start и выполнить `python3 tg.py setup`: скрипт найдёт ваш chat id и пришлёт тестовое сообщение.
3. Поставить расписание (10:07 и 20:07):
   ```sh
   cp launchd/local.shop-watch.plist ~/Library/LaunchAgents/
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.shop-watch.plist
   ```

Проверить без отправки: `uv run --script watch.py --print`.

## история заказов

`ozon_orders` и `ali_orders` ищут по названиям купленных товаров: `query` — слова, которые все должны встретиться в названии или варианте. Несколько вариантов можно искать за один вызов через «|»: `usb хаб | hub`. В списках заказов обоих сайтов названий нет, поэтому сервер открывает каждый заказ отдельным запросом, примерно по 1,5–2 с. Всё прочитанное лежит в `cache/orders.json`: завершённые заказы навсегда, заказы в пути на сутки (статус берётся из свежего списка), и сами списки заказов. Список обновляется сверху, пока не попадётся страница без новых заказов. Архив Ozon за прошлые годы после первого прочтения больше не запрашивается. Первый полный проход по нескольким сотням заказов занимает минут десять. Дальше обычный поиск идёт секунды, а повторный в течение 10 минут не делает ни одного запроса.

## ограничения

- Сайты меняют вёрстку и API, и тогда разбор ломается.
- Авито при частых запросах включает проверку и отвечает 439. Сервер делает паузы между запросами, но капчу иногда приходится проходить руками в этом Chrome.
- Регион Авито по умолчанию — `sankt-peterburg`, меняется параметром `region`.
- Скрытый Chrome: страницы и API работают, но клики — только в видимой активной вкладке. Поэтому адрес в `avito_item` и `ali_add_to_cart` требуют `shop-chrome show` и открытой вкладки сайта; без этого инструмент так и отвечает. Chrome 154 уводит скрытые вкладки в фоновый приоритет macOS, и на загруженном Mac они стоят; флаг `ForceForegroundPriorityForAllTabs` в plist это отключает.
- Wildberries и Золотое яблоко подписывают запросы токеном или городом из профиля, поэтому их данные берутся из ответа, который получила сама страница (`capture.py`). Следующие страницы WB сайт грузит только при прокрутке, поэтому страница N — это его собственный запрос первой страницы с подменённым номером.
- Корзина WB синхронизируется с сервером подписанным запросом, поэтому операции едут в теле собственной синхронизации страницы, а удаление делается как у сайта: строка убирается из корзины в браузере и ставится в его очередь операций. Корзина Маркета меняется только кликами (строки ищутся по sku, а не по тексту кнопок: в шапке корзины есть «Удалить» для всех выбранных).
- Wildberries и Яндекс Маркет на запрос без совпадений показывают посторонние товары. Маркет на странице отдаёт только часть выдачи (8–40 карточек), дальше — следующие страницы.
- Используйте на свой страх и риск: автоматизация может противоречить правилам сайтов.
