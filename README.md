# shop-mcp

MCP-сервер для поиска на Авито, Ozon, AliExpress, Wildberries, Яндекс Маркете, Lamoda и в Золотом яблоке под своим аккаунтом. Он управляет обычным Chrome, в котором вы уже вошли на эти сайты, и отдаёт результаты компактным TSV, а не снимками страниц. Так поиск стоит сотни токенов, а не десятки тысяч.

Что умеет:

- Авито: поиск с ценой доставки в ваш город и итоговой суммой, карточка объявления с адресом.
- Мессенджер Авито: список чатов, переписка в чате, отправка текстового сообщения в чат или продавцу объявления.
- Ozon: поиск, карточка товара (характеристики, дата доставки, продавец и его юрлицо: видно, из-за рубежа ли товар), корзина (положить, посмотреть, убрать), история заказов с поиском по названию товара.
- AliExpress: поиск, карточка с датами доставки и всеми вариантами (sku, цена, остаток), корзина, история заказов с поиском по названию товара.
- Wildberries: поиск (страницы по 100, сортировки, цена), карточка (продавец, наличие, оценка срока доставки, характеристики), корзина (посмотреть, положить, убрать).
- Яндекс Маркет: поиск (страницы, сортировки, цена) с ценой с картой Я Банка и без, пометками продвижения и «из-за рубежа»; карточка с магазином и доставкой; корзина (посмотреть; положить и убрать — только в видимой вкладке).
- Lamoda: поиск с итоговой ценой со всеми скидками и размерами в наличии; карточка с остатками по размерам и возвратом; корзина (посмотреть, положить, убрать).
- Золотое яблоко: поиск (страницы по 24, сортировки, цена), карточка с ценой и наличием каждого объёма, составом и применением, корзина (посмотреть, положить, убрать).
- Продукты питания (`grocery_*`): Лента, Самокат, Яндекс Лавка, Перекрёсток, Пятёрочка, ВкусВилл — поиск по названию и тегам («без лактозы», «без сахара», «веган»…), состав по ингредиентам и КБЖУ, сравнение одного товара между магазинами и выбор по составу, отзывы, корзина и избранное. Подробнее — раздел «продукты питания».
- Отзывы покупателей на всех площадках, кроме Авито (`*_reviews`): дата, звёзды, «полезно», размер и цвет, текст, ссылки на фото, на WB и Ozon ещё видео. Сортировки и фильтр «только с фото».
- Подробная карточка (`*_item`): скидки в %, доставка на ваш адрес, ссылки на фото, описание целиком с `full=True`; на WB история цены по неделям.
- Картинки по ссылке (`shop_images`): фото товара и отзывов, которые модель видит сама; до 6 за вызов.
- Отзывы на Ozon и AliExpress от вашего имени: список купленного, что ждёт отзыва, и отправка отзыва с оценкой и текстом.

Заказы сервер не оформляет и ничего не оплачивает: всё заканчивается на корзине.

## как устроено

Chrome запускается по требованию: его открывает первый инструмент, которому нужна вкладка сайта, а подключение клиента и список инструментов его не трогают. Дальше он остаётся открытым, пока его не закроют. При входе в macOS он не запускается, после ⌘Q сам не открывается: снова его поднимет следующий вызов. Несколько сессий, вызвавших инструменты одновременно, запускают один экземпляр. Он работает с отдельным профилем и `--remote-debugging-port=9222` на 127.0.0.1. Сервер подключается к нему по DevTools Protocol, держит по одной вкладке на сайт и вызывает собственное API сайта через `fetch()` изнутри вкладки. Cookies и авторизация остаются в профиле Chrome, в коде их нет.

Каждая установка самостоятельна: свой Chrome-профиль на своём Mac со своими входами на сайты. В репозитории нет ничьих данных. Всё личное остаётся в профиле Chrome (`~/Library/Application Support/shop-chrome`) и в `logs/` и `cache/`, которые не попадают в git.

## установка

Шаги рассчитаны на то, что их выполнит агент (Claude Code или другой) на Mac пользователя. Сам пользователь делает только шаг 3: входит на сайты.

Нужно: macOS, Google Chrome в `/Applications`, git и [uv](https://docs.astral.sh/uv/) (`brew install uv` или `curl -LsSf https://astral.sh/uv/install.sh | sh`).

1. Клонировать репозиторий в `~/shop-mcp` — пути в скриптах рассчитаны на это место:

   ```sh
   git clone https://github.com/YolisStormbreaker/shop-mcp.git ~/shop-mcp
   ```

2. Поставить отдельный Chrome для магазинов — одна команда, её можно повторять (она же чинит установку):

   ```sh
   ~/shop-mcp/shop-chrome setup
   ```

   Она ставит LaunchAgent `local.shop-chrome`: Chrome по требованию (не при входе в систему) с отдельным профилем `~/Library/Application Support/shop-chrome` и отладочным портом 9222 только на 127.0.0.1, окно прячется, у процесса своя иконка в Dock. Основной Chrome пользователя не затрагивается. Ещё она кладёт `shop-chrome` в `~/.local/bin`, ждёт, пока Chrome откроет порт, и говорит, чего не хватает (uv, вход на сайты). Если этот шаг пропустить, сервер при первом вызове выполнит `setup` сам.

   Убрать совсем: `launchctl bootout gui/$(id -u)/local.shop-chrome` и удалить `~/Library/LaunchAgents/local.shop-chrome.plist`.

3. Вход на сайты — делает пользователь, агент пароли не вводит. `shop-chrome show` показывает окно: в нём войти на нужные сайты (Авито, Ozon, AliExpress, Wildberries, Яндекс Маркет, Lamoda, Золотое яблоко; продукты — Лента, Самокат, Яндекс Лавка, Перекрёсток, Пятёрочка) и указать адрес доставки, затем `shop-chrome hide`. У продуктовых магазинов адрес обязателен: от него зависят ассортимент, цены и корзина. Вкладки сайтов не закрывать. Без входа работает только поиск, с ценами и доставкой для региона по умолчанию; корзины и история заказов — только после входа.

4. Подключить к MCP-клиенту:
   - Claude Code: `claude mcp add shop -s user -- ~/shop-mcp/run.sh`, затем `claude mcp list` — `shop … ✔ Connected`.
   - Claude Desktop: в `~/Library/Application Support/Claude/claude_desktop_config.json`, раздел `mcpServers`, добавить `"shop": {"command": "/Users/ИМЯ/shop-mcp/run.sh"}` (полный путь: `~` там не раскрывается) и перезапустить приложение через ⌘Q.
   - Cursor, VS Code, Codex и другие: stdio-сервер с командой `/Users/ИМЯ/shop-mcp/run.sh`.

   Первый запуск скачивает зависимости Python, до минуты. Инструменты появляются в новых сессиях клиента.

5. Проверить: в новой сессии вызвать, например, `ali_search` с запросом «скрепки» — придёт таблица товаров. Ответ с «⚠️» — сайт просит пройти проверку: `shop-chrome show`, пройти её во вкладке сайта, повторить.

6. По желанию, для Claude Code: разрешить без подтверждения инструменты, которые только читают. В `~/.claude/settings.json` добавить в `permissions.allow`:

   ```json
   "mcp__shop__avito_search", "mcp__shop__avito_item", "mcp__shop__ozon_search", "mcp__shop__ozon_item",
   "mcp__shop__ozon_orders", "mcp__shop__ali_search", "mcp__shop__ali_item", "mcp__shop__ali_orders",
   "mcp__shop__wb_search", "mcp__shop__wb_item", "mcp__shop__ym_search", "mcp__shop__ym_item",
   "mcp__shop__lamoda_search", "mcp__shop__lamoda_item", "mcp__shop__goldapple_search", "mcp__shop__goldapple_item",
   "mcp__shop__wb_reviews", "mcp__shop__ozon_reviews", "mcp__shop__ali_reviews", "mcp__shop__ym_reviews",
   "mcp__shop__lamoda_reviews", "mcp__shop__goldapple_reviews", "mcp__shop__shop_images", "mcp__shop__shop_status",
   "mcp__shop__grocery_search", "mcp__shop__grocery_item", "mcp__shop__grocery_compare",
   "mcp__shop__grocery_compare_composition", "mcp__shop__grocery_reviews"
   ```

   Инструменты корзины и избранного (`*_cart`, `*_add_to_cart`, `*_remove_from_cart`, `grocery_favorite*`) лучше оставить с подтверждением.

Как пользоваться инструментами и что работает, а что нет, сервер сообщает агенту сам: в инструкциях при подключении и в описаниях инструментов.

**Если что-то не работает** — сначала `shop-chrome status` (агенту то же даёт инструмент `shop_status`): что установлено, запущено ли, отвечает ли порт, не обновился ли Chrome, не новый ли профиль.

- Chrome закрыли (⌘Q) или он упал — следующий вызов инструмента запустит его сам (`shop-chrome start`) и подождёт порт, этот вызов дольше на 10–15 с. Вручную — `shop-chrome start`; `shop-chrome show` тоже сначала запустит закрытый Chrome. Если агент выгружен, `start` вернёт его (`launchctl bootstrap`). Завис уже запущенный — `shop-chrome restart`.
- Chrome удалён — сервер так и ответит: «Google Chrome не установлен». Поставить Chrome, затем `shop-chrome setup`.
- Профиль удалён или это новый пользователь — Chrome создаст пустой профиль, сайты будут без входа; `shop-chrome status` пишет «профиль новый». Повторить шаг 3.
- Сайт пишет «⚠️ … проверка на бота» — `shop-chrome show`, пройти проверку во вкладке сайта, `shop-chrome hide`.
- Все инструменты падают по таймауту — `ps -axo pri,stat,command | grep renderer | grep shop-chrome`. Приоритет 4 в состоянии R значит, что Chrome увёл вкладки в фоновый приоритет macOS: после обновления Chrome перестала действовать фича `ForceForegroundPriorityForAllTabs` в plist.
- Иконка в Dock снова обычная — `shop-chrome icon`.
- Chrome обновился (status пишет «обновился до …, а запущен …») — `shop-chrome restart`, затем снова `status`.
- Обновиться: `cd ~/shop-mcp && git pull && ./shop-chrome setup` — `setup` переустановит LaunchAgent, если его шаблон в `launchd/` изменился (Chrome при этом перезапустится). Изменения модулей сервер подхватывает сам, но список инструментов и инструкции клиент получает только при запуске сервера. После обновления перезапустите клиент: Claude Desktop — ⌘Q и открыть снова, Claude Code — новая сессия. Пока этого не сделано, ответы инструментов начинаются с «⚠️ Сервер shop запущен со старой версией». Без перезапуска Claude Desktop, например, не видит раздел продуктов и ищет еду на Ozon.

Лог вызовов пишется в `logs/shop.log`, тела неудачных ответов — в `logs/bodies/`. В них бывают данные со страниц сайтов, поэтому `logs/` в `.gitignore`.

## мониторинг Авито в Telegram

`watch.py` ищет по всей России с Авито Доставкой новые Orange Pi Zero3 для пульта фрезера, у которых цена с доставкой не больше 5 000 ₽ (с 11.10.2026, до этого искал Raspberry Pi 4 и 5). Память любая, сверху дешёвые. Зарезервированные пропускает. Каждое объявление присылает один раз. Запросы и порог цены задаются в начале файла.

1. Создать бота у @BotFather и положить токен в `telegram.json`: `{"token": "..."}`.
2. Написать боту /start и выполнить `python3 tg.py setup`: скрипт найдёт ваш chat id и пришлёт тестовое сообщение.
3. Поставить расписание (10:07 и 20:07):
   ```sh
   cp launchd/local.shop-watch.plist ~/Library/LaunchAgents/
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.shop-watch.plist
   ```

Проверить без отправки: `uv run --script watch.py --print`.

## история заказов

`ozon_orders` и `ali_orders` ищут по названиям купленных товаров: `query` — слова, которые все должны встретиться в названии или варианте. Несколько вариантов можно искать за один вызов через «|»: `usb хаб | hub`. В списках заказов обоих сайтов названий нет, поэтому сервер открывает каждый заказ отдельным запросом, примерно по 1,5–2 с. Всё прочитанное лежит в `cache/orders.json`: завершённые заказы навсегда, заказы в пути на сутки (статус берётся из свежего списка), и сами списки заказов. Список обновляется сверху, пока не попадётся страница без новых заказов. Архив Ozon за прошлые годы после первого прочтения больше не запрашивается. Первый полный проход по нескольким сотням заказов занимает минут десять. Дальше обычный поиск идёт секунды, а повторный в течение 10 минут не делает ни одного запроса.

## мессенджер Авито

`avito_chats` показывает чаты, новые сверху, `unread_only=True` — только непрочитанные. `avito_chat` показывает переписку в одном чате. Оба читают через сокет самого мессенджера (`wss://socket.avito.ru`), который сервер открывает изнутри вкладки Авито, и не отмечают чаты прочитанными. Сокет живёт на странице и переиспользуется: новое соединение сразу после закрытого Авито не обслуживал.

`avito_send` отправляет текст от вашего имени: в чат по id из `avito_chats` или продавцу по ссылке на объявление. Сервер открывает чат на странице (у объявления — кнопкой «Написать сообщение»), вводит текст в поле и нажимает Enter, как человек. Потом ищет сообщение в истории чата и отвечает «отправлено» только если нашёл. Фото и файлы не отправляются.

## продукты питания

Запросы про еду и напитки сервер направляет сюда, а не на маркетплейсы: если магазин не назван, агент ищет сразу во всех продуктовых (`grocery_compare`) и предлагает ещё маркетплейсы; в спорных случаях (корм для животных, бытовая химия, витамины, спортпит) спрашивает, где искать.

Все магазины — одно семейство инструментов `grocery_*` с параметром `store`: `lenta`, `samokat`, `lavka`, `perekrestok`, `5ka`, `vkusvill`. Цены, наличие и корзина — для адреса доставки, указанного на сайте.

- `grocery_search` — поиск по названию и/или тегу. Тег — диетический раздел или фильтр сайта («без лактозы», «без сахара», «веган», «халяль», «фермерское», «без добавления сахара»); ответ перечисляет теги, которые сайт понимает. Если тега нет, ищет текстом и пишет об этом.
- `grocery_item` — карточка: цена, скидка, цена за кг/л, наличие, доставка, характеристики, фото и **состав, разобранный на ингредиенты**: пронумерованный список (ингредиенты идут по убыванию доли), проценты («какао-продукты не менее 72%»), на каком месте сахар (или сироп, мёд, декстроза; отдельно — сахар внутри компонента, например в томатном соусе), подсластители, пальмовое масло, ароматизаторы, крахмал, Е-добавки, следы аллергенов, КБЖУ на 100 г.
- `grocery_compare` — один запрос во всех магазинах сразу: таблица с ценой за кг/л, одинаковые товары собраны в группы (штрихкодов сайты не отдают — совпадение по фасовке, процентам и словам названия). Соседние товары, которые сайты подмешивают в поиск, отсеиваются.
- `grocery_compare_composition` — выбрать лучшее: состав и КБЖУ первых товаров каждого магазина (или выбранных `items`), по порядку `rank`: цена за кг/л, сахар, калории, белок, жир, длина состава или доля ингредиента (`%какао`, `%томат`, `%мясо`). У каждого товара — ссылка.
- `grocery_reviews`, `grocery_cart`, `grocery_add_to_cart`, `grocery_remove_from_cart`, `grocery_favorites`, `grocery_favorite`.

| магазин | как устроено | состав, КБЖУ | сахар | отзывы | корзина | избранное |
|---|---|---|---|---|---|---|
| Лента | переход внутри приложения и ответы страницы; поиск — собственный запрос страницы с нашим телом | да | нет (только фильтр «Сахар») | 5 последних | кнопки страницы | кнопка страницы |
| Самокат | эндпоинты и store самого сайта в открытой вкладке, без переходов | да | нет | нет | thunk сайта | нет на сайте |
| Яндекс Лавка | API сайта из вкладки (у дома и Большая лавка) | да + аллергены и теги | только тег «без сахара» | нет | кнопки страницы | API |
| Перекрёсток | API-клиент сайта из вкладки | да | нет | да, с фото | API | API |
| Пятёрочка | API каталога из вкладки | да | нет | да, без фото | кнопки страницы | нет на сайте |
| ВкусВилл | публичный API ВкусВилла (поиск, карточки) + вкладка (наличие, отзывы, корзина, избранное) | да | **да**, общий и добавленный | да | кнопки страницы | запрос сайта |

Сахар сайты почти не пишут отдельно; тогда в ответе «сахара ≤ углеводов». Перекрёсток, Пятёрочка и Самокат стоят за защитой ServicePipe: после долгой серии запросов с одного IP она показывает проверку на бота, и инструмент так и отвечает — пройти её в `shop-chrome show`. Сервер делает паузы между запросами к ним, чтобы не включать её. ВкусВилл ищет через свой публичный каталог (https://mcp.vkusvill.ru/mcp, без авторизации, 60 запросов в минуту) — отдельно его подключать не нужно.

## отзывы покупателей и картинки

`wb_reviews`, `ozon_reviews`, `ali_reviews`, `ym_reviews`, `lamoda_reviews`, `goldapple_reviews` читают отзывы о товаре: общий рейтинг и, где сайт его даёт, распределение звёзд; по каждому отзыву дату, звёзды, «полезно», вариант, автора, текст и ссылки на фото. Сортировки: `useful`, `new`, `high`, `low` (на Ozon нет `new`). `with_media=True` оставляет отзывы с фото.

Что отдаёт каждый сайт:

| сайт | откуда | страницы | фото | видео |
|---|---|---|---|---|
| Wildberries | публичный API отзывов, без браузера (браузер нужен один раз, чтобы узнать номер карточки) | до ~1000 отзывов с текстом, сортировка и страницы — у нас | да | да: HLS `index.m3u8` и превью |
| Ozon | страница отзывов сайта | по 30, переход на страницу N | да | да: mp4 и превью |
| AliExpress | API списка отзывов | по 10 | да | нет в API |
| Яндекс Маркет | страница отзывов, сортировка кликом | только первые 10 на сортировку: остальные сайт грузит прокруткой видимой страницы | да | — |
| Lamoda | API страницы товара | любые, все цвета модели или один | да | нет в API |
| Золотое яблоко | API страницы товара | по 20 | да | — |

У Авито отзывов на товары нет, только рейтинг продавца.

На Ozon продавцы иногда склеивают под один рейтинг разные товары: на одной карточке набора было 141 отзыв на сам товар и 663 на все склеенные. Тогда смотрите `this_variant=True`. AliExpress после серии запросов показывает проверку-слайдер и, пока она открыта, держит все запросы вкладки: сервер через 25 с отвечает «⚠️ … проверка на бота», пройти её — `shop-chrome show`.

`shop_images` скачивает картинки по ссылкам (до 6 за вызов) и возвращает их модели как изображения, уменьшенные до `max_side` пикселей. Копии лежат в `cache/images`. Ссылки берутся из строки «фото (shop_images)» в `*_item` и из отзывов. Скачиваются только http(s)-адреса в интернете: локальные и внутренние адреса отклоняются, в том числе после редиректа. CDN всех семи сайтов отдают картинки без cookies, поэтому браузер для этого не нужен.

## отзывы от вашего имени

`ozon_reviews_waiting` и `ali_reviews_waiting` показывают купленные товары, которые ждут отзыва. `ozon_leave_review` и `ali_leave_review` публикуют отзыв от вашего имени: оценку от 1 до 5 и текст. Сервер шлёт его тем же запросом, что и форма отзыва на сайте.

Ozon находит товар по sku. AliExpress — по строке заказа из списка, потому что один товар бывает в нескольких заказах. Фото и видео не прикладываются. Уже оставленный отзыв инструмент не редактирует.

Ozon при оценке ниже 4 требует текст. Если за отзыв на товар дают баллы, Ozon перед отправкой показывает условия. Тогда отзыв не уходит, а инструмент возвращает условия; отправить всё равно можно с `accept_conditions=True`. На AliExpress отзыв проходит модерацию, это до 48 часов.

В описании инструментов модели сказано брать оценку и смысл текста только у вас и показывать отзыв перед отправкой.

## ограничения

- Сайты меняют вёрстку и API, и тогда разбор ломается.
- Авито при частых запросах включает проверку и отвечает 439. Сервер делает паузы между запросами, но капчу иногда приходится проходить руками в этом Chrome.
- Регион Авито по умолчанию — `sankt-peterburg`, меняется параметром `region`.
- Скрытый Chrome: страницы и API работают, но клики — только в видимой активной вкладке. Поэтому адрес в `avito_item` и `ali_add_to_cart` требуют `shop-chrome show` и открытой вкладки сайта; без этого инструмент так и отвечает. Chrome 154 уводит скрытые вкладки в фоновый приоритет macOS, и на загруженном Mac они стоят; флаг `ForceForegroundPriorityForAllTabs` в plist это отключает.
- Wildberries и Золотое яблоко подписывают запросы токеном или городом из профиля, поэтому их данные берутся из ответа, который получила сама страница (`capture.py`). Следующие страницы WB сайт грузит только при прокрутке, поэтому страница N — это его собственный запрос первой страницы с подменённым номером.
- Корзина WB синхронизируется с сервером подписанным запросом, поэтому операции едут в теле собственной синхронизации страницы, а удаление делается как у сайта: строка убирается из корзины в браузере и ставится в его очередь операций. Корзина Маркета меняется только кликами (строки ищутся по sku, а не по тексту кнопок: в шапке корзины есть «Удалить» для всех выбранных).
- Фото в `avito_item` пока не проверены на живой странице: в день доработки Авито отвечал «проблема с IP». Главное фото берётся из `og:image`, остальные — из галереи.
- Wildberries и Яндекс Маркет на запрос без совпадений показывают посторонние товары. Маркет на странице отдаёт только часть выдачи (8–40 карточек), дальше — следующие страницы.
- Используйте на свой страх и риск: автоматизация может противоречить правилам сайтов.
